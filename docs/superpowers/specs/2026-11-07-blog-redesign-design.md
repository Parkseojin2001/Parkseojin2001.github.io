# 블로그 리디자인 설계

- 작성일: 2026-11-07
- 브랜치: `redesign`
- 기반: Jekyll + Chirpy 7.3 (소스를 저장소에 직접 보유, GitHub Actions로 빌드·배포)

## 1. 목적

**개인 블로그가 기본**이고, 여기에 **프로젝트를 잘 보여주는 기능을 추가**한다.

- PDF 포트폴리오는 분량·링크·이미지·업데이트에 한계가 있어서, 프로젝트마다 웹 페이지를 두고 이력서에 링크를 건다.
- 지금 디자인은 "md를 잘 보여주는 정도"라 개성이 없으므로 사이트 전체 디자인을 바꾼다.

### 성공 기준

1. 블로그 자체가 "내 사이트"라는 느낌이 들 만큼 디자인에 개성이 있다.
2. 프로젝트 페이지 링크 하나로 PDF보다 프로젝트를 더 잘 보여줄 수 있다.
3. 글 쓰고 관리하는 흐름은 지금처럼 편하다(오히려 스크립트로 더 편해진다).
4. 기존 글 184개의 주소가 하나도 바뀌지 않는다.

### 범위에서 제외

- en/ko 다국어: 추후 기능. 단, 나중에 `.en.md`를 추가하기 어렵게 만드는 구조는 피한다.
- 깨진 이미지 21장 교체: 별도 작업.
- 다른 프레임워크(Astro 등)로 이전.

## 2. 구현 접근법

**Chirpy를 기반으로 개조한다.**

- 유지: 검색, 목차, 다크 모드 전환, 코드 하이라이트·복사, MathJax, Mermaid, utterances 댓글, 이미지 확대, PWA, SEO, sitemap, feed
- 교체: 전체 틀(`_layouts/default.html`의 왼쪽 사이드바·오른쪽 패널 → 상단바), 색·글꼴(SCSS), 홈·블로그 목록 레이아웃
- 추가: `_projects` 컬렉션과 레이아웃, 카테고리 트리, devlog 연결, 필수 항목 검사 플러그인, 글 생성 스크립트

선택하지 않은 대안: 레이아웃·CSS를 처음부터 새로 작성(검색·목차·수식 등을 모두 다시 구현해야 함), 다른 프레임워크로 이전(이번 목표에 비해 과함).

## 3. 디자인 스타일

시안 B(개발자 터미널) + A(미니멀)를 섞은 **v5**로 확정.

### 원칙

- 첫인상(로고·인사말·메뉴)은 깔끔하게, 내용을 나누는 라벨에서 개발자 느낌을 낸다.
- 큰 제목과 본문은 일반 글꼴, 메타 정보와 라벨은 고정폭 글꼴.

| 요소 | 표현 |
|---|---|
| 로고 | `● Seojin Park` (점만 포인트 색, 일반 글꼴) |
| 메뉴 | `Projects  Blog  About` (일반 글꼴) |
| 홈 첫 라벨 | `HELLO, I'M SEOJIN` (고정폭, 포인트 색) |
| 섹션 라벨 | `./projects`, `./now`, `./blog`, `./categories`, `./devlog` (고정폭) |
| 글 목차 라벨 | `// 목차` (고정폭) |
| 글 위치 표시 | `blog / data-engineering / spark` (고정폭) |
| 날짜·태그·기술 스택·코드 | 고정폭 |
| 제목·본문 | 일반 글꼴 |

- 모든 화면은 다크·라이트 둘 다 지원한다.

## 4. 사이트 구조와 URL

```
/                         홈 (새 레이아웃)
├── /projects/            프로젝트 목록
│   └── /projects/<이름>/  프로젝트 상세
├── /blog/                블로그 목록 (10개씩)
│   └── /blog/page<N>/    다음 페이지
├── /about/               소개
├── /categories/ /tags/ /archives/   유지 (새 스타일)
└── 기존 글 주소           전부 그대로
```

- 상단 메뉴: `● Seojin Park` · Projects · Blog · About · 검색 · 테마 전환
- Categories·Tags·Archives는 상단 메뉴에서 빼고 블로그 페이지 안에서 연결한다.
- 바뀌는 주소: 기존 홈 목록 페이지 `/page<N>/` → `/blog/page<N>/` (`paginate_path: "/blog/page:num/"`, 블로그 목록은 `blog/index.html`).
- 바뀌지 않는 주소: 글, 카테고리, 태그, `/feed.xml`, `/sitemap.xml`.

## 5. 페이지별 구성

### 공통 틀

- 상단바: 스크롤해도 위에 고정, 모바일에서는 메뉴가 햄버거 버튼으로 접힘. 검색은 Chirpy의 기존 검색(simple-jekyll-search)을 상단바로 옮긴다.
- 푸터: 저작권, GitHub·이메일 링크.
- 제거: 왼쪽 사이드바, 오른쪽 "최근 업데이트·인기 태그" 패널.

### 홈 `/`

1. `HELLO, I'M SEOJIN` + 큰 제목 + 한 줄 소개 + 관심 분야 태그
2. `./projects`: `featured: true`인 프로젝트를 `order` 순으로 최대 3개 카드(썸네일, 이름, 한 줄 소개, 기술 스택)
3. `./now`: `_data/now.yml`의 카드 2~4개
4. `./blog`: 최근 글 5개(제목, 날짜, 카테고리)
5. `./categories`: 상위 카테고리 버튼과 글 개수

### 프로젝트 목록 `/projects/`

- 카드 그리드(데스크톱 3열, 태블릿 2열, 모바일 1열), `order` 오름차순 정렬.

### 프로젝트 상세 `/projects/<이름>/` (B안)

- 왼쪽(본문 영역): 위치 표시 `projects / <이름>`, 제목, 한 줄 소개, 대표 이미지, 본문(md)
- 오른쪽(고정 영역, 스크롤 따라옴): 기간, 팀, 내 역할, 기술 스택, 링크 버튼. 그 아래에 `// 목차`(`toc: true`일 때)
- 본문 아래 `./devlog`: `project: <이름>`이 붙은 글을 날짜순으로 나열. 하나도 없으면 영역 자체를 표시하지 않는다.
- 모바일: 오른쪽 고정 영역이 제목 아래 요약 카드로 내려온다.

### 블로그 목록 `/blog/` (B안)

- 왼쪽: 카테고리 트리. 글의 `categories[0]`(상위)·`categories[1]`(하위)로 만들고 글 개수를 표시한다. 상위 항목 앞의 `▸/▾` 화살표는 하위 목록을 접고 펴고, 카테고리 이름을 누르면 기존 카테고리 페이지로 이동한다. 처음에는 모두 접힌 상태다.
- 오른쪽: 글 목록(제목, `description`, 날짜, 카테고리), 10개씩 페이지 나눔.
- 모바일: 트리가 목록 위쪽 접이식 메뉴로 바뀐다.

### 블로그 글 페이지

- 위치 표시, 제목, 날짜·읽는 시간·태그
- 본문은 일반 글꼴, 오른쪽 `// 목차`는 스크롤을 따라온다.
- 유지: 이전·다음 글, 관련 글, 댓글, 수식, Mermaid, 코드 복사
- `project:`가 있으면 제목 위에 `↳ project: <프로젝트 제목>` 링크를 표시한다.

### About `/about/`

- 틀만 작성: 소개 문단, 기술 스택, 경력·활동, 연락처. 내용은 사용자가 채운다.

### 카테고리·태그·아카이브

- 기능은 유지하고 새 스타일만 적용한다.

## 6. 콘텐츠 종류와 데이터 구조

### 세 종류

| 종류 | 파일 위치 | 이미지 폴더 | 보이는 곳 |
|---|---|---|---|
| ① 일반 포스트 | `_posts/<카테고리 폴더>/` | `assets/img/post/<주제>/` | 블로그 |
| ② 개발 기록 | `_posts/projects/<프로젝트>/` | `assets/img/post/projects/<프로젝트>/` | 블로그 + 프로젝트 페이지 `./devlog` |
| ③ 프로젝트 완성본 | `_projects/<이름>.md` | `assets/img/projects/<이름>/` | 프로젝트 목록·상세, 홈 |

- ②는 일반 post이고 `project:` 한 줄만 추가된다. 블로그 목록·검색·RSS·카테고리에 그대로 포함된다.
- ②의 카테고리는 글 성격에 따라 정한다: 공부 내용은 주제 카테고리(예: `[AI Agent, LangChain]`), 진행 기록·회고는 `[Projects, <프로젝트 이름>]`.
- 이미지 규칙: 이미지를 쓰는 글과 같은 구조의 폴더에 둔다. 같은 이미지를 여러 글에서 쓸 때는 파일 하나를 경로로 공유한다.

### 컬렉션 설정 (`_config.yml`)

```yaml
collections:
  projects:
    output: true
    permalink: /projects/:name/
```

프로젝트 기본값(`defaults`): `layout: project`, `toc: true`, `comments: false`.

### ③ 프로젝트 front matter

```yaml
title: RAG 기반 사내 문서 챗봇           # 필수
summary: 사내 문서를 근거로 답하는 LLM 챗봇  # 필수
period: 2026.03 – 2026.06               # 필수
role:                                   # 필수 (목록)
  - 검색 파이프라인 설계 및 구현
stack: [Python, LangChain, FastAPI]     # 필수 (목록)
team: 4인 팀 (백엔드·ML 담당)            # 선택
links:                                  # 선택, 키 이름 자유 → 버튼 라벨
  github: https://github.com/...
  demo: https://...
thumbnail: /assets/img/projects/rag-chatbot/thumbnail.png  # 선택, 없으면 기본 이미지(카드 배경색 + 프로젝트 제목 첫 글자)
featured: true                          # 선택, 기본 false
order: 1                                # 선택, 기본 99
toc: true                               # 본문 기능
math: false
mermaid: true
comments: false
```

### ② 개발 기록 front matter (일반 포스트 + `project`)

```yaml
title: "..."
description: "..."
categories: [AI Agent, LangChain]
tags: []
project: rag-chatbot          # _projects/rag-chatbot.md 의 파일 이름
permalink: /projects/rag-chatbot/vector-db-comparison/
toc: true
math: false
mermaid: false
date: 2026-11-07
```

- 글 하나는 프로젝트 하나에만 연결한다.

## 7. 필수 항목 검사 플러그인

`_plugins/project-validator.rb` (Jekyll 훅, `site` 읽기 후 실행)

- 각 프로젝트에 `title`, `summary`, `period`, `role`, `stack`이 비어 있지 않은지 검사한다.
- `project:`가 붙은 글이 존재하는 프로젝트를 가리키는지 검사한다(오타 감지).
- 문제가 있으면 파일 경로와 항목 이름을 담은 **경고**를 `Jekyll.logger.warn`으로 출력한다. 빌드는 중단하지 않는다.

## 8. 글 생성 스크립트 `tools/new.sh`

- 실행: `bash tools/new.sh` (대화형). macOS 기본 bash 3.2에서 추가 설치 없이 동작한다.
- 흐름:
  1. 종류 선택: 1) 일반 포스트 2) 개발 기록 3) 프로젝트
  2. 종류별 추가 질문
     - 일반 포스트: 기존 `_posts/` 하위 카테고리 폴더 목록에서 선택하거나 새 경로 입력
     - 개발 기록: `_projects/` 목록(파일 이름 + 제목)에서 선택
     - 프로젝트: 없음
  3. 파일 이름 입력(영어 소문자·숫자·하이픈만)
- 생성:
  - 글 파일(오늘 날짜 접두사, 프로젝트는 날짜 없음)과 템플릿 front matter. 각 항목에 `[필수]`/`[선택]`과 작성 안내를 주석으로 단다.
  - 프로젝트 템플릿 본문에는 `## 문제 정의`, `## 아키텍처`, `## 내가 한 일`, `## 결과` 뼈대와 안내 주석을 넣는다.
  - 이미지 폴더(없을 때만)
  - permalink 기본값: 일반 포스트는 `/<카테고리 폴더>/<이름>/`, 개발 기록은 `/projects/<프로젝트>/<이름>/`
- 출력: `✓ 글 파일`, `✓ 이미지 폴더 (새로 만듦 | 이미 있음)`, `✓ 주소`, (개발 기록) `✓ 연결`, 그리고 "다음 할 일"(채울 항목, 이미지 사용 예시 경로)
- 실패 처리:
  - 이름 규칙 위반 → 다시 입력 요청
  - 같은 파일이 이미 있음 → 덮어쓰지 않고 종료(종료 코드 1)
  - 개발 기록인데 프로젝트가 없음 → 프로젝트부터 만들라고 안내하고 종료

## 9. 작업 순서

`redesign` 브랜치에서 단계마다 커밋한다.

1. **기본 틀**: 상단바·푸터, 사이드바·패널 제거, 색·글꼴, 다크 기본, 글 페이지 스타일
2. **블로그**: `/blog/` 목록·카테고리 트리, 페이지 나눔 이동, 카테고리·태그·아카이브 스타일
3. **프로젝트**: 컬렉션, 상세·목록 레이아웃, devlog 연결, 글 상단 프로젝트 링크, 검사 플러그인
4. **홈**: 새 홈 레이아웃, `_data/now.yml`
5. **About**: 틀
6. **스크립트**: `tools/new.sh`
7. **최종 점검** 후 `main`에 합치기

3단계에는 예시 프로젝트가 필요하다. 사용자가 실제 프로젝트 정보를 주면 그것으로, 없으면 `published: false` 샘플로 작업한다.

## 10. 확인 방법

1. `JEKYLL_ENV=production bundle exec jekyll build`가 에러 없이 끝나고 검사 플러그인 경고가 없다.
2. 개편 전후 빌드 결과의 HTML 경로 목록을 비교한다. 사라져도 되는 것은 `/page<N>/`뿐이고, 글 184개·카테고리·태그·`feed.xml`·`sitemap.xml`은 모두 남아 있어야 한다.
3. `html-proofer`(Gemfile `test` 그룹)를 `--disable-external` 옵션으로 실행해 사이트 내부 링크·이미지만 검사한다. 외부 이미지 깨짐은 별도 작업이므로 이 검사에서 제외한다.
4. 필수 항목을 비운 테스트 프로젝트와 없는 프로젝트를 가리키는 테스트 글로 경고가 실제로 뜨는지 확인한다.
5. 임시 복사본에서 스크립트로 세 종류를 모두 만들고 빌드되는지 확인한다. 덮어쓰기 방지, 이름 규칙 위반, 프로젝트 없음도 확인한다.
6. 단계마다 로컬 미리보기를 데스크톱·모바일 폭, 다크·라이트로 확인하고, 마지막에 사용자가 직접 확인한다.
7. `npm test`(stylelint)를 통과한다.
